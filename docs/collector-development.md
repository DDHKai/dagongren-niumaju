Node 22+，无npm依赖，使用全局fetch/WebSocket。必须已有用户自己登录的隔离Chrome CDP，端口仅监听本机；不读取日常浏览器配置，不绕过验证、不导出Cookie、不发起沟通。启动隔离Chrome及登录尚未产品化接入网页，不能称开箱可用。

```text
node scripts/collect_jobs.mjs --config examples/collector-config.json --output data/private-market/run-001 --endpoint http://127.0.0.1:9333
```

示例配置仅为通用业务/数据检索，并非个人方向判断；用户需根据已确认条件设置城市及关键词。默认目标100不同平台公司，上限200岗位详情；不含翻页/滚动，关键词首屏不足时明确覆盖不足，不能声称全市场覆盖。只有一个BOSS标签可自动选择，否则需显式--tab-id；不使用固定本机tab ID。

checkpoint保存配置hash、搜索/岗位/公司原文、时间、失败代码和未评审状态。同输出不能暗改配置；已成功岗位去重，同公司不同岗位保留。平台验证/登录/连接超时停止，当前未完成岗位允许用户修复环境后续跑；普通页面失败记录并跳过，不无限自动重试。不要同时操作同一个标签或并发写同一输出目录。

仅从岗位“公司基本信息”明确容器获取公司链接，推荐链接、多个不同主体、找不到容器均不绑定公司；匿名岗位保留，但不计为已知主体覆盖。平台路径去重不是法定主体核验，集团关系还需后续研究。本轮选择器已小批核对，未来变化仍可能产生未知或覆盖不足，应诊断后修正，不靠降低身份判断标准凑100家。

## 显式追加关键词续搜（main新增）

同输出目录默认仍拒绝配置变化。需要扩容时保留原配置，在新配置末尾追加不重复关键词，其他字段逐项不变，执行：

`node scripts/collect_jobs.mjs --config "新配置.json" --previous-config "原配置.json" --output "原采集目录" --endpoint http://127.0.0.1:9333`

工具验证旧配置hash确属原检查点，拒绝换城市、修改目标数/详情上限/等待、替换关键词及重复追加。先将旧checkpoint原字节留档为checkpoint-before-extension-时间戳.json，再写带configHistory的新检查点，保留岗位、公司、失败与搜索历史，继续按原ID去重。不可并发运行，首次执行前另做完整私有备份；再次续跑直接用新配置，不重复传旧配置。详情总上限仍按整轮attemptedJobs计数，已达上限时保持覆盖不足，不自动提高。若原配置不可得或hash不匹配，停止，不从报告猜配置。需要登录／验证由主人本人处理，不绕过平台验证。

杭州AI电商扩容可评估AI投放、智能投放、AIGC运营、电商数据分析、AI电商运营等相关关键词，去掉原配置已有项；这些是本轮搜索探索，不宣称用户具备相应技能。原工作区固定18K与双休等条件不变。新检查点登记后需重算预筛、重点能力复核和结果；原选择不自动继承。报告区分100平台公司数量覆盖与深评数量、有效雇佣机会及匿名主体，不凑10+10，不将请求上限或首屏限制解释成全市场搜索完成。原60家公司数据只在测试设备，开发设备不能以HTML反造原始证据。
