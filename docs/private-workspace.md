# 本地真实简历工作区

## 给 WorkBuddy／本地执行助手的对话入口

用户入口是对话，工作区是执行与留证工具。先确认当前客户端有本地文件、命令执行和专用Chrome访问能力；缺少能力时明确告知，不声称所有豆包／WorkBuddy客户端都支持。读取README、固定Release及包内文档；只下载Release资产与SHA256，校验并解压到新目录。下载直链失败可以尝试GitHub官方API资产端点，仍须与发布SHA256比对，不关闭TLS校验。不覆盖旧项目、用户材料或旧测试现场。

对用户只提出当前必要问题：

1. “简历是否已更新？可以提供本地简历；也可由你登录BOSS后读取。”先提取原文、展示经历摘要与待确认信息，由用户确认；不自动勾选所有事实。
2. “本轮方向、城市、薪资和休息要求是什么？”保存用户原话。“18K以上”不自动解释成固定底薪或区间下限，追问一次口径；固定底薪作为硬条件时保留未知，若用户同意可另展示发布区间值得探索的岗位，不改原条件。
3. 仅在需要时让用户本人登录专用Chrome。不索取密码、验证码、Cookie，不操作日常浏览器配置。默认只读采集；收藏另需具体岗位明确授权，沟通及投递由本人完成。

## 助手执行与结果留证顺序

按本文及[能力复核](ability-review.md)、[结果汇总](result-report.md)执行已有工作区接口，不要求用户逐节填写开发页面。助手可以代整理原文与起草判断，必须标记是助手复核草稿；不得把助手判断写成本人确认。接口的reviewerConfirmed表示实际执行者明确核对过证据，不是用户已确认；涉及本人事实、选择与授权时仍须取得对应确认。

采集检查点 → 按已确认口径预筛 → 每个重点岗位生成能力草稿并引用已确认经历 → 保存片段复核与缺口 → 公司研究保存已知或未知 → 生成结果 → 取得本轮名单选择确认 → 保存选择及本人顺序 → 私人范围确认后导出HTML/JSON并验证实际落盘。使用服务器当前版本字段和令牌，不手写成功状态、不修改SQLite绕过校验。已有工作区POST入口为 `/api/result-generate`、`/api/result-choose`、`/api/result-reorder`、`/api/result-export`；请求字段以当前 `workspace_server.py` 及页面调用为准，不按旧对话猜字段。接口拒绝过期或缺证据时补齐来源并重新生成，不能改成独立HTML绕过。

该链路仍由有本地执行能力的外部助手编排；仓库不包含大模型服务或一键自主决策引擎，不声称本段文档本身实现了自动匹配。无法完成复核时输出部分结果和待办，不冒称完整名单。报告可补充排版，但内置JSON/HTML应为可追溯主产物；另外排版须附对应报告版本，不改变状态或覆盖计数。

## 输出约束与停止点

- 先报告可识别去重公司数／100、岗位数、数量覆盖不足、能力复核数、公司研究数。平台主体数与有效公司数分开；匿名岗位单列，同公司多岗位不重复。排除类别可能重叠，不相加当成公司数。
- 优选、候选、取舍／探索分别展示。硬条件未知只能候选，明确学历或休息不符只能取舍；不因行业热门或公司大而越过硬条件。5个探索线索不叫5个完全合适岗位，不凑10+10。
- “0个有证据确认全部条件”不等于没机会；只说明本次样本。15—30K和底薪+提成不能推出18K必靠提成；应问固定部分、绩效、提成与试用期。发布区间不是本人报价。
- 校招、招商／加盟线索先保留本岗位原句与适用对象，区分明确不适用与待核实；当前预筛没有自动识别这些属性，助手人工判断须单独记录，不冒称程序已过滤。
- 三项建议固定为真实经历重点、具体核实问题、不匹配处。简历调整只给草稿，不编造AI技能或业绩，不自动修改线上意向，不承诺回复率或面试机会。
- 默认一轮目标100家公司；不足时沿原轮次追加搜索并去重，不悄悄改城市、薪资或休息。采集器当前仅首屏，不能承诺翻页已实现。遇登录、安全验证或采集异常保留断点并请求必要协助，不绕过验证。
- 所有履历引用、岗位选择、原始检查点与报告均属私有资料，不能因去姓名就上传GitHub。公开反馈只留版本、匿名计数、失败位置和未实现能力。

## 最小对话验收

### 事实确认的执行者与范围

事实现在分别保存助手原文核对 `sourceReview` 与本人确认 `confirmation`，各含声明执行者、方式、时间、单条事实范围及历史。工作区 `/api/confirm` 可传 `actor=assistant, method=source-check`：只留原文核对记录，不把未确认事实升为 candidate-confirmed，不满足正向能力判断门槛。取得本人对明确事实范围的确认后，传 `actor=candidate`，方式为 `explicit-fact-selection` 或 `explicit-scoped-batch`。批量范围以显式factIds记录，不能把校对映射、部署或导出许可视为确认。

CLI同样支持：`python scripts/resume_workspace.py confirm --output "候选版本目录" --fact-id "实际事实ID" --actor assistant --method source-check`。本人按范围确认后改用candidate与对应方式。默认candidate仅兼容旧调用，不代表身份校验；记录 identityVerified=false，执行者声明可被错误调用，系统无法证明本人在场。助手不得因默认值就替本人确认。

旧事实没有confirmation记录时显示“历史确认，确认方式未记录”，不自动补造时间、执行者或证据，也不批量撤销历史。助手核对原文不能抵消或撤销此前错误的本人确认；发现误确认必须按新版本纠正流程处理。确认记录参与事实hash，新记录使旧能力／结果失效，需要重算；不自动继承旧选择。当前报告仍可能保留旧状态，不能仅凭candidate-confirmed断言已完成可信身份认证。

用户只需交给助手仓库链接、回答简历与条件问题，并在需要时本人登录。验收看是否产生同一轮次的预筛、能力复核、公司记录与内置结果导出，重点候选能回到原文；未做环节必须显式列出。测试记录用户介入位置、助手额外脚本、卡点与实际耗时。不得用成功部署或另制HTML替代完整任务验收。

main开发能力，尚未纳入既有合成实验Release。仅本机运行，没有模型、岗位采集、财报查询或投递。

## 启动

需要Python 3.10+。PDF另需在自己的环境按requirements-resume.txt安装pypdf；DOCX/TXT/JSON无第三方解析依赖。

Windows在项目根目录：

```text
start-windows.bat --workspace
```

macOS终端：

```sh
sh ./start-macos.command --workspace
```

直接命令：`python scripts/workspace_server.py`（macOS使用python3）。默认前者从8765、后者从8875尝试20个本机端口。可指定`--no-browser`、`--port`、`--data`；地址由终端输出，Ctrl+C停止。默认数据位置data/private-web，不随停止或刷新清空。macOS新工作区未实机回归，旧合成页通过不能自动继承。

## 页面操作

1. 填写必须、偏好、不在意，每行一个条件；当前保存文本，不自动解析、打分或执行筛选。
2. 选择自己的PDF/DOCX/UTF-8 TXT/JSON并导入；原文件留在本地。JSON需符合experiences格式，TXT不推断公司/职位。
3. PDF/DOCX按页/段展示文字；请另开本地原文件视觉对照，复杂版式/字体可能缺失。扫描件无OCR，不能直接确认成有效履历。
4. 添加工作/教育经历。每个字段选择原文单元、粘贴精确片段，点击加入引用；跨页可以多个引用。错误引用可移除；不凭空填公司、时间、业绩。
5. 勾选已核对字段与条件，再保存新版本。保留历史版本文件，界面当前仅打开最新版本；不覆盖旧输入。
6. 勾选确已核对的事实，点击确认。没有默认全选；本人确认不等于独立核实。TXT/JSON可直接进入事实审阅，也可保存新的条件版本；正文修正目前应重新导入新记录。
7. 刷新记录列表、选择ID打开，可恢复最新版本与确认状态。界面没有删除按钮/加密/多用户权限，不要将共享电脑作为无保护简历库。

## 数据与访问边界

原文、映射、条件、版本、事实盐均在选择的数据目录，默认被Git忽略。源码白名单不包含这些数据。无API下载日志、无遥测、不调用外部模型；第8节经明确确认可请求固定官方财报文档，不发送简历。使用边界见[公司研究](company-research.md)。服务不提供任意文件目录浏览。

仅绑定127.0.0.1，检查Host、来源及每次启动的随机令牌，API不设置跨域许可；页面禁缓存、禁止嵌入。令牌不打印、不放URL、不持久化。其他本机用户/进程若有文件权限仍可能访问资料，这不是账户隔离或恶意文件沙箱。仅导入自己信任的文档，不开放公网，不同时启动多个写入同一数据目录的实例。

导入失败可能仍保留原文件与失败记录，本地保存不代表加密。停止服务后可自行备份/管理私有目录，分享前不要打包整个目录。此前“演示页内存日志”的描述不适用于本工作区。
